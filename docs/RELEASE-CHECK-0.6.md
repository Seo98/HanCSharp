# v0.6.0 검증 기록

2026-11-10 / Windows x64 / Unity 6000.3.25f1 / Visual Studio 2022.

## 구현과 책임

- `HanCSharpAssetPresentation`: Project 창의 한 아이콘, 자산 Inspector 원본·미리보기 버튼, 컴포넌트 컨텍스트 메뉴. 기존 사용자 Inspector를 대체하지 않는다.
- `HanCSharpWorkbench` 및 UXML/USS: 읽기 전용 비교 화면과 오류 행 열기. 외부 변환은 백그라운드에서 실행하며 이전 요청·닫힌 창의 결과는 반영하지 않는다.
- `HanCSharpPreview`: 임시 파일 변환과 정리. Unity API에 의존하지 않고 원본·실제 생성 C#을 수정하지 않는다.
- `KoreanToCSharp`·CLI: 코드 출력과 동시에 원본 행 목록을 기록한다. 원문 문자열의 `#line`을 제거하는 방식이 아니므로 원문을 보존한다.
- `HanCSharpSourceMap`: 생성 C#의 내용 해시와 원본 경로를 검증한 뒤 행을 연결한다. 수정된 생성 파일에는 이전 매핑을 적용하지 않는다.
- `HanCSharpDiagnostics`: 실제 Unity 컴파일 이벤트의 오류를 원본 행으로 정리한다. Console 내부 API를 가로채지 않는다.
- `HanCSharpProjectIntegration`: 사용자 확장자를 보존하며 han을 등록하고, 설정된 Unity 코드 편집기 연결을 우선해 파일·행을 연다.

## 실제 Unity와 편집기

별도 검증 프로젝트에만 Pipeline을 설치했다. 제품 템플릿에는 포함하지 않는다.

- Unity에서 새 에디터 코드를 컴파일하고 UXML/USS를 가져왔다.
- Project 창의 청록색 한 아이콘과 한씨 자산 Inspector의 두 버튼을 육안 확인했다.
- 원본 열기 버튼을 실제 클릭해 `.han` 파일이 외부 편집기에 열리는 것을 확인했다.
- 실제 미리보기에서 한국어 원본과 C# 결과, 두 개의 읽기 전용 영역과 변환 성공 상태를 확인했다.
- 문법 오류 원본을 따로 만들어 미리보기가 원본 4행 HCS001을 표시하고 오류 행 버튼을 활성화하는 것을 확인했다. 미리보기는 생성 C#을 만들지 않았다.
- 설정된 코드 편집기 연결을 이용해 Visual Studio 2022에서 해당 한씨 4행에 커서가 이동하는 것을 확인했다. 기본 앱 열기 API만 사용할 때 행 번호가 유실되는 경우를 보강했다.
- 실제 Unity C# 컴파일에서 문자열을 정수에 대입하는 CS0029 오류를 만들었다. 생성 C# 6행을 한씨 7행으로 연결한 오류 목록이 표시됐고, 실제 버튼을 눌러 Visual Studio의 `.han` 7행에 커서가 이동하는 것을 확인했다. 검증용 오류 파일은 정리하고 자동 생성을 복구했다.

## 한계

미리보기는 저장된 파일만 읽는다. 변환 성공은 Unity 자료형·어셈블리 참조 검사가 끝났다는 뜻이 아니다. C# 의미 오류는 Unity Console에서 확인한다. 원본 행을 연결하며 정확한 원본 열 번호, 실시간 빨간 밑줄, 전체 C# 타입 추론, 한씨 원본 중단점은 제공하지 않는다. 기본 앱 열기로 돌아가는 외부 편집기에서는 행 이동 지원이 제한될 수 있으므로 Unity의 External Script Editor를 해당 편집기로 설정해야 한다.

변경 범위는 에디터 도구와 변환 메타데이터다. 이동 예제의 입력·이동 컴포넌트 책임과 Inspector 수치 연결은 유지한다. 실제 게임 전체나 모든 Unity/IDE 버전의 호환성을 검증한 것은 아니다.

# 영어 단어를 한글로 바꾸는 것만으로 충분할까?

한씨를 처음 만들 때는 C#의 영어 키워드를 한국어로 바꾸는 데 집중했다. 하지만 코드를 읽어 보니 단어만 한글일 뿐, 한국어 문장처럼 자연스럽게 읽히지는 않았다. 내가 만들고 싶은 것은 번역된 키워드 목록보다 **읽으면서 뜻을 이해할 수 있는 코드**에 가깝다.

영어는 보통 주어·동사·목적어 순서로 말하고, 한국어는 주어·목적어·동사 순서로 말한다. 프로그래밍 언어가 영어 문장을 그대로 따르는 것은 아니지만, 한국어로 작성하는 코드라면 한국어의 문맥과 어순도 설계에 반영해야 한다고 생각했다.

예를 들어 행동을 먼저 적는 `출력 "안녕".`보다 다음 문장이 읽기 쉽다.

```text
컴퓨터는 "안녕"을 출력한다.
```

**컴퓨터는 → 인사말을 → 출력한다.** 무엇이 무엇을 하는지 문장 순서대로 알 수 있다. 변수도 `정수 체력은 100이다.`에서 시작하기보다, 처음 배우는 사람에게는 `체력은 100이다.`로 소개하고 필요할 때 값의 종류를 알려 주는 편이 낫다고 봤다.

Unity에서도 같은 방향을 적용했다.

```text
이 물체는 오른쪽으로 초당 이동속도만큼 움직인다.
```

목표는 초등학생이나 프로그래밍을 처음 배우는 사람도 문장을 읽고 행동을 예상하며 코드를 작성할 수 있게 하는 것이다. 이것이 실제로 얼마나 쉬운지는 앞으로 사용자에게 써 보게 하며 확인해야 한다.

모든 한국어 문장을 자유롭게 이해하는 언어를 지향하는 것은 아니다. **정해진 문장 틀은 단순하게, 읽는 순서는 한국어답게, 실행은 C#과 Unity에 연결되게** 만드는 것이 현재의 방향이다.

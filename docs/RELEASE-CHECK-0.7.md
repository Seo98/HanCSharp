# v0.7.0 검증 기록

2026-11-10 / Windows x64 / .NET 9 / Unity 6000.3.25f1.

## 구현 범위

- 지역·멤버 함수의 반환형 생략(void), 자연스러운 동안 조건, 번호 없는 정수 횟수 반복.
- 한씨 식의 참·거짓, 실수32(float)·실수64(double) 별칭.
- 조건·반복·함수·클래스·이름공간 종료 종류 확인. 기존 끝. 유지.
- 기존 C# 이름을 보존하는 구문 단위 논리값 처리, 문자열·주석·멤버명·C# 원문 보호.
- 역변환의 새 함수·반복 표현, 원본 행 매핑 유지.
- VSIX 0.7.0의 자료형·키워드 색상과 새 문장 템플릿·반환형 생략 함수 매개변수 완성.
- 새 LanguageTour 콘솔 예제, Unity 기본 템플릿과 예제의 반환형 생략·실수32 적용.

Visual Studio 확장 Release 빌드는 경고 0·오류 0이며 동일 확장 ID의 버전을 0.7.0으로 높였다. 최신 자동완성 사용에는 새 VSIX 설치가 필요하다. 이번 검증에서는 실행 중인 사용자 Visual Studio를 닫거나 설치된 확장을 강제로 교체하지 않았다. 새 DLL/VSIX 빌드와 공유 완성·색상 로직을 검증했으며 실제 IDE에서의 업그레이드 설치는 별도 범위다.

## 실제 실행

LanguageTour 예제가 체력 3/2/1, 반복 세 번, float/double 값을 정상 출력했다.

기존 검증용 Unity 프로젝트의 외부 CLI와 입력·이동 원본을 업데이트했다. 새 한씨 문법으로 만든 별도 MonoBehaviour를 Unity가 실제 컴파일한 뒤 Play Mode에서 생성했다. Start에서 참·거짓, 실수32·실수64, 3번 반복, 자연스러운 동안 조건, 종류를 명시한 종료를 실행한 결과가 기대한 상태인지 실제 프로퍼티로 확인해 통과했다. 일반 C# 스텁 실행과 구분한다. 검증용 소스는 제품 템플릿에 넣지 않는다.

반환형 생략과 실수32로 바꾼 입력·이동 예제도 Play Mode에서 WASD·방향키, 대각선, 키 해제 후 정지, 입력 비활성화 시 정지를 통과했다. Input System 합성 키보드 이벤트를 사용했으며 물리 키보드의 전 키 수동 검증과는 구분한다.

## 호환 범위

`실수`는 계속 double이며 기존 없음 반환형·동안 접두형·번호 있는 반복·끝.도 지원한다. 논리값은 파일 안의 같은 이름 선언을 우선 보존한다. 외부 파일의 동명 심벌은 `@참` 또는 `대상.참`처럼 구분한다. 프로젝트 전체 이름 분석을 수행하지 않는다. C# 원문과 특성 인수 등 원문 표기에서는 true/false를 사용한다.

번호 없는 반복은 정수 리터럴만 지원하며 횟수 식은 기존 이름 있는 반복을 사용한다. 반환형 생략은 추론이 아니라 void다. 역변환은 동작을 보존하는 지원 범위의 변환이며 원래 표기까지 복원하지 않는다.

## 공개 배포 확인

[v0.7.0 GitHub Windows 빌드](https://github.com/Seo98/HanCSharp/actions/runs/42668532975)가 성공했다. 공개 ZIP을 인증 없이 재다운로드해 첨부 해시와 일치함을 확인했다. SHA-256: `1fd729653d3148598e69149de4e31b6312d8f9b6a06b63f23e28e458ad2abdb0`.

깊은 한글 다운로드 폴더에서 콘솔 예제, 짧은 새 프로젝트 준비와 반복 준비, 런타임·UI 리소스를 확인했다. ZIP에는 0.7 VSIX만 포함되며 내부 확장 버전은 0.7.0이었다. 공개 self-contained CLI에서 LanguageTour 실행, C#과 별도 행 매핑 생성, 역변환 결과의 재실행·출력 일치, 잘못된 종료의 원본 2행 진단이 통과했다. Unity의 실제 실행 검증은 위 QA 프로젝트에서 수행했으며 재다운로드한 새 프로젝트의 첫 Unity 가져오기를 별도로 반복하지는 않았다.

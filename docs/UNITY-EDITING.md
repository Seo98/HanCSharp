# 한씨 원본 열기·변환 미리보기·오류 위치

v0.6.0 / Unity 6000.3.25f1에서 확인한 에디터 기능입니다.

## 수정할 파일 찾기

Project 창에서 청록색 **한** 아이콘이 붙은 파일이 `.han` 원본입니다. C# 아이콘은 Unity가 컴파일하는 `.cs`입니다. Unity의 확장자 숨김 때문에 같은 이름으로 보이더라도 아이콘으로 구분할 수 있습니다.

1. `Assets/HanCSharp/Examples/HanObjectMover.han`을 한 번 선택합니다.
2. Inspector 상단의 **한씨 원본 열기**를 누릅니다.
3. Unity에 설정된 외부 편집기가 원본을 엽니다. Visual Studio에 이미 열린 `.cs` 탭은 자동 교체되지 않습니다.

한씨가 생성한 `.cs` 자산을 선택해도 같은 버튼이 나옵니다. GameObject에 붙은 컴포넌트에서는 컴포넌트의 ⋮ 메뉴에서 **한씨 원본 열기**를 선택할 수 있습니다. 일반 사용자 C#에는 원본 연결을 만들지 않습니다. 기존 컴포넌트의 Inspector를 커스텀 에디터로 대체하지 않습니다.

## 나란히 비교하기

Inspector의 **변환 미리보기**, 또는 **Tools → HanCSharp → 변환 미리보기**를 누릅니다.

- 왼쪽: 저장된 `.han` 원본과 원본 행 번호.
- 오른쪽: 해당 원본을 변환한 C#과 생성 행 번호.
- 가운데 경계를 드래그해 두 영역의 폭을 조절할 수 있습니다.
- 외부 편집기에서 저장한 뒤 **저장된 원본 새로고침**을 누릅니다.
- Project 창에서 다른 한씨 파일을 선택하면 해당 원본을 표시합니다.

두 영역은 읽기 전용입니다. 미리보기는 `Library/HanCSharp/Preview`의 고유 임시 파일에서 변환하고 정리하며 원본이나 실제 생성 C#을 덮어쓰지 않습니다. 변환 중 원본이 바뀌면 다시 새로고침하도록 안내합니다. 아직 저장하지 않은 Visual Studio 편집 내용은 읽지 않습니다.

## 오류 위치로 이동하기

마침표·조사·블록 문법 오류는 미리보기에 `원본.han(행,열): error HCS001` 형식으로 나옵니다. **오류 행 열기**를 누르면 외부 편집기에서 해당 원본 행으로 이동합니다. 변환 성공은 Unity 자료형·참조 검사가 끝났다는 뜻은 아닙니다.

자료형 불일치나 없는 이름 같은 C# 컴파일 오류는 Unity에서 컴파일한 뒤 **변환 미리보기의 Unity C# 오류 목록**에서 `한씨 N행 열기`를 누릅니다. 실제 Unity 컴파일 이벤트를 받아 생성과 함께 저장한 별도 행 매핑으로 원본 행을 찾습니다. Unity Console이 C# 파일을 직접 여는 버전에서도 이 목록을 사용할 수 있습니다. 열 번호까지 일치하는 기능이나 실시간 빨간 밑줄은 제공하지 않습니다.

- **Emit Source Map 꺼짐(기본)**: C#은 간결하게 유지합니다. 미리보기의 오류 목록이 `Library/HanCSharp/Maps`의 별도 매핑을 사용합니다. Unity Console 자체의 더블클릭은 C# 위치를 열 수 있습니다.
- **Emit Source Map 켜짐**: C#에 `#line`을 넣어 Unity 컴파일러가 원본 경로·행으로 진단합니다. Console 자체에서도 원본 진단을 보려면 켠 뒤 Generate All을 실행하세요.
- 문법 변환에 실패하면 이전 C#을 실행하지 않도록 컴파일을 차단하고, 차단 오류도 원본의 실패 행에 연결합니다.
- 사용자가 생성 C#을 수정했거나 매핑이 없으면 해당 C# 위치를 유지합니다. 잘못된 한씨 행으로 이동하지 않습니다. **Generate All**로 다시 생성하면 매핑이 복구됩니다.
- 일반 C# 파일의 오류 이동은 기존 동작을 유지합니다.

## 기존 설치에서 업데이트

새 버전 체험은 새 Releases ZIP의 시작 창에서 **② Unity 이동 예제 준비·실행**을 누르는 방법을 권장합니다. 버전별 폴더라 이전 예제를 보존합니다.

기존 프로젝트는 먼저 소스 관리에 커밋하거나 백업하세요. 기존 파일이 다르면 설치 도구는 덮어쓰지 않고 중단합니다. 비교 후 `Assets/HanCSharp/Editor`의 도구 코드·UXML·USS와 `Tools/HanCSharp`의 CLI·런타임을 **같은 배포 버전으로 함께 갱신**해야 합니다. 기존 `.meta`와 GUID는 유지하고 사용자 예제 및 Settings 자산을 일괄 교체하지 마세요. v0.6 에디터만 복사하고 이전 CLI를 사용하면 새 행 매핑 옵션을 처리할 수 없습니다.

갱신 후 Unity로 돌아가 컴파일을 기다리고 **Tools → HanCSharp → Generate All**을 실행하세요. v0.5에서 작업하던 예제는 자동 이동하거나 덮어쓰지 않습니다.

# v0.5.0 배포 검증

검증일: 2026-11-08 / Windows x64 / Unity 6000.3.25f1.

## 변경

- PowerShell 창 대신 .NET Framework 4.7.2 기반 네이티브 시작 창을 제공한다.
- 다운로드 위치에서 Unity를 직접 열지 않는다. 압축된 템플릿을 기본적으로 문서 폴더의 `HanCSharp/MovementDemo-0.5.0`에 준비한다. 문서 경로가 길면 LocalAppData를 시도하고, 저장 위치를 직접 고를 수도 있다. Unity 대상 경로는 80자 이하로 제한한다.
- 운영체제 레지스트리 설정을 바꾸지 않는다. Unity 엔진 자체의 긴 경로 제약은 남아 있으며, 기존 프로젝트를 자동 이동하지 않는다.
- 같은 버전의 준비된 예제는 사용자 수정을 보존하며 다시 연다. 소유 표시가 없는 폴더와 내용이 다른 기존 설치 파일을 덮어쓰지 않는다.
- 예제 준비 후 컴파일이 끝나면 이동 씬을 연다. 저장하지 않은 다른 씬은 유지한다.
- Unity 6.3의 obsolete InstanceID API 대신 EntityId API를 사용한다. 이전 Unity에는 조건부 분기를 둔다.
- HealthState 예제의 nullable 문맥을 명시해 CS8669를 없앴다.
- 실험적 Pipeline 패키지는 제품 템플릿에 포함하지 않는다.

## 실제 실행

깊게 중첩된 한글 다운로드 폴더에 후보 ZIP을 새로 풀고 시작 창을 열었다. 자동 콘솔 예제에서 75/50/25/0을 확인했다. 실제 **② Unity 이동 예제 준비·실행** 버튼을 눌러 짧은 문서 경로에 준비되고 Unity가 실행되는 것을 확인했다. 이동 씬이 자동으로 열렸으며 첫 컴파일과 Play에서 Console 경고 0·오류 0이었다.

수치 검증을 위해 해당 검증 프로젝트에만 Pipeline을 추가했다. 실제 Play Mode에서 Input System 키보드 이벤트를 넣어 WASD 4방향, 방향키 4방향, W+D 대각선, 입력 컴포넌트 비활성화를 확인했다. 모든 이동 방향과 키 해제 후 정지, 대각선 입력 정규화, 비활성화 시 정지가 통과했다. 이는 합성 키보드 이벤트 검증이며 사람이 물리 키보드로 모든 키를 누른 검증은 아니다. 검증 도구는 제품 템플릿과 분리했다.

## 자동 검증

| 범위 | 결과 |
|---|---|
| 언어 변환·실제 C# 컴파일·왕복 실행 | 26개 통과 |
| 편집기 색상·완성 목록·문장 템플릿 | 12개 통과 |
| Unity 연결 API 모형 및 실제 외부 변환기 호출 | 20개 통과 |
| 설치·짧은 경로 준비·수정 보호·ZIP 경로 이탈 방지 | 9개 통과 |
| 네이티브 시작 프로그램 Release 빌드 | 경고 0·오류 0 |

PowerShell 설치 래퍼와 네이티브 CLI 종료 코드 및 UTF-8 출력을 확인했다. 기존 Unity 프로젝트 설치 후 변환기와 에디터 파일이 복사되는 것도 확인했다.

## 범위와 한계

Unity와 Visual Studio는 별도 설치 대상이다. Unity 6000.3.25f1이 설치되지 않았으면 시작 창에서 `Unity.exe`를 선택하거나 Unity Hub로 준비된 프로젝트를 열어야 한다. Unity의 최초 패키지 다운로드에는 인터넷이 필요하다. 새 PC에서 운영체제부터 설치한 검증은 아니며, 기존 Unity·Visual Studio가 있는 이 Windows 환경에서 새 폴더로 확인했다. VSIX의 기능은 이전 실제 VS 검증과 이번 12개 회귀 검증에 근거하며, v0.5.0에서 VSIX 자체는 변경하지 않았다.

이전 배포에서 발견한 긴 경로 오류와 경고의 원인은 [v0.4.0 기록](RELEASE-CHECK.md)에 남겨 두었다.

## 공개 후 재다운로드 확인

[v0.5.0 공개 Release](https://github.com/Seo98/HanCSharp/releases/tag/v0.5.0)에서 인증 없이 Windows ZIP과 SHA256SUMS.txt를 다시 받았다. ZIP의 SHA-256은 `86296d5ae11552ec883c10aa0103ed3bf6ddb9d528bf8d2ec94b46ccc1e4fb99`이며 첨부 해시와 일치했다.

새로운 깊은 한글 폴더에 풀어 네이티브 시작 창의 한글 콘솔 출력과 내장 가이드 버튼을 확인했다. 공개 ZIP의 도구로 별도의 짧은 프로젝트 폴더를 새로 준비했고 런타임 복사·씬 열기 요청·반복 준비 시 파일 보존이 통과했다. 템플릿에 Pipeline이 포함되지 않는 것도 확인했다.

[GitHub Windows 빌드](https://github.com/Seo98/HanCSharp/actions/runs/42478028665)도 성공했다. 언어·완성·설치 검증, VSIX 빌드, 네이티브 시작 프로그램 및 Windows 실행 ZIP 빌드가 포함된다. 공개 첨부 ZIP의 로컬 실행 검증과 CI 산출물 빌드는 별도로 수행했다.

## v0.5.1 첫 초기화 보강

v0.5.0 공개 ZIP으로 만든 완전한 새 프로젝트에서 최초 이동 씬 열기 요청이 처리되지 않는 경우를 발견했다. 프로젝트의 절대 경로와 Editor 업데이트 알림을 사용하고 SceneAsset 등록이 끝날 때까지 기다리도록 수정했다. 실제 같은 프로젝트에서 수정 후 자동으로 이동 씬이 표시되고 Console 오류 0인 것을 확인했다.

최신 배포는 [v0.5.1](https://github.com/Seo98/HanCSharp/releases/tag/v0.5.1)이다. 공개 ZIP을 다시 다운로드해 해시 일치·한글 출력·새 프로젝트 준비·반복 준비를 확인했다. SHA-256: `5555d2a7bef9ba1c248236b8bbb2c77156b4c996c72bfe53a3855d6ebce5bdf5`. [v0.5.1 GitHub Windows 빌드](https://github.com/Seo98/HanCSharp/actions/runs/42478579923)도 성공했다.

재다운로드한 v0.5.1로 캐시가 없는 별도 프로젝트를 준비해 Unity에서 처음 열었다. 이동 씬의 자동 표시와 요청 파일의 정상 소비, 첫 컴파일 후 Console 경고 0·오류 0을 확인했다.

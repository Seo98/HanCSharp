# v0.8.0 검증

검증 환경: 2026-11-10 / Windows x64 / Unity 6000.3.25f1. 이 기록은 자동 테스트, 실제 Unity 에디터 검증, 배포 파일 검사를 구분합니다.

## 자동 검증

- 언어 변환·왕복·행 매핑 36개 통과.
- 자동완성·색상·템플릿 14개 통과.
- Unity 연결 모형 27개 통과.
- 기존 설치·짧은 경로 준비 회귀 10개 통과. 과거 Launcher 소스의 회귀 확인이며 v0.8 EXE 배포를 뜻하지 않습니다.
- 신규 안전한 업데이트·저장 감지 16개 통과.

총 103개. 새 검증은 교체 전 백업, 사용자 변경 충돌, 예제/meta 보존, 알려진 이전 버전 해시만 허용, 검사 후 저장 재확인, 스테이징 변조, 실패 시 롤백, 경로 이탈/중복 ZIP/EXE 거부, 다운그레이드 거부, 연속 저장 합치기와 변환 중 저장 대기를 포함합니다.

## 실제 Unity

- 실제 AssetDatabase.ExportPackage로 Assets/HanCSharpInstaller만 추출했습니다. 압축 포맷을 흉내 낸 파일이 아닙니다.
- 비어 있는 새 QA 프로젝트에 최종 unitypackage를 가져와 내장 payload를 검사했습니다. 84개 파일 추가 계획, .NET 실행 확인과 적용 버튼 활성화를 확인했습니다.
- 새 설치 적용 후 예제 5개의 C# 생성과 Unity 컴파일 성공을 확인했습니다. 설치 도구·DLL·예제만 추가하고 씬·입력 설정은 변경하지 않습니다.
- 설치된 QA에서 갱신 대상 3개 파일의 실제 교체와 백업 해시 일치를 확인했습니다.
- 설치된 Editor 파일에 사용자 주석을 추가했을 때 충돌과 전체 적용 차단, 버튼 비활성화, 수정 내용 보존을 확인하고 QA 변경을 복구했습니다.
- Auto Generate를 끄고 미리보기에서 최초 표시·저장·연속 저장의 최종 내용·자동 갱신 끄기/다시 켜기·원본 삭제를 확인했습니다. 실제 C#은 생성되지 않았습니다.
- 기존 이동 씬에서 실제 Play Mode에 진입하고 Game 화면에 포커스를 준 뒤 Input System 키 상태를 주입했습니다. WASD·방향키 8방향, 대각선 정규화, 키 해제 정지, 입력 컴포넌트 비활성 정지를 확인했습니다. 물리 키를 사람이 길게 눌러 검사한 결과와는 구분합니다.

## 이전 버전과 런타임

- 고정한 공개 v0.5.0·v0.5.1·v0.6.0·v0.7.0 ZIP 해시를 먼저 확인하고 도구별 알려진 해시 목록 230개 경로를 생성했습니다.
- 공개 v0.7.0 ZIP의 실제 Editor/DLL 파일로 별도 파일시스템 설치를 구성해 v0.8 검사·적용을 실행했습니다. 7개 교체와 백업, 최종 manifest 해시 일치를 확인했습니다. 전체 과거 프로젝트의 Unity 씬 이관 테스트를 의미하지 않습니다.
- 최종 설치 DLL을 `dotnet --fx-version 10.0.14`로 강제 실행하고 한씨 프로그램의 `.NET 10.0.14` 출력을 확인했습니다. net9.0 DLL의 Major roll-forward 설정도 검사했습니다.

## 배포 구조

unitypackage는 설치 도구·내장 압축 데이터·안내문만 포함합니다. Payload의 manifest 84개 파일 SHA-256이 모두 일치하고 EXE가 없습니다. .NET Runtime은 사용자가 직접 설치합니다. 선택 VSIX는 문법이 같은 0.7을 유지합니다.

공개 파일 재다운로드와 온라인 최신 배포 조회 결과는 배포 후 아래에 추가합니다.

## 검증 범위

Windows x64의 위 Unity 버전을 확인했습니다. macOS/Linux, 다른 Unity 버전, 다른 네트워크 환경, .NET이 전혀 없는 새 운영체제에서의 런타임 설치 화면, Visual Studio 확장의 실제 업그레이드 설치는 별도 확인이 필요합니다. SHA-256은 파일 무결성 검사이며 독립적인 전자서명이 아닙니다. Unity 컴파일 성공과 사용자 프로젝트의 모든 게임 규칙 검증은 구분해야 합니다.

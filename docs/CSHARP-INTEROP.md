# C#과 한씨 함께 사용하기

같은 Unity 프로젝트에서 `.han`과 직접 작성한 `.cs`를 함께 사용할 수 있습니다. 한씨가 일반 C# 클래스를 생성하므로 공개 클래스·메서드를 서로 호출할 수 있습니다. asmdef를 사용하는 프로젝트에서는 기존 Unity 어셈블리 참조 규칙을 따릅니다.

## C# 클래스를 한씨에서 호출

직접 만든 `DamageCalculator.cs`:

```csharp
public static class DamageCalculator
{
    public static int Calculate(int attack, int defense)
    {
        return System.Math.Max(0, attack - defense);
    }
}
```

한씨 함수 안에서:

```text
정수 damage는 DamageCalculator.Calculate(35, 10)이다.
출력 damage.
```

API 호출과 식 내부는 C# 표기입니다. Unity 게임 로그에는 `출력` 대신 `기록 damage.`를 사용할 수 있습니다.

## 한씨 클래스를 C#에서 호출

`ScoreState.han`:

```text
공개 봉인 클래스 ScoreState:
    비공개 필드 정수 _score는 0이다.
    공개 속성 정수 Score는 _score이다.

    공개 함수 Add(정수 amount)는 없음:
        _score에 amount를 더한다.
    끝.
끝.
```

생성 완료 후 C#에서:

```csharp
var state = new ScoreState();
state.Add(10);
UnityEngine.Debug.Log(state.Score);
```

## 생성 파일과 일반 C# 구분

생성 파일 첫 줄에는 `// <auto-generated by HanCSharp> source=...` 표식이 있습니다. 이 파일을 직접 수정하면 다음 한씨 변환에서 바뀝니다. 같은 이름의 직접 작성한 C#이 있으면 변환기는 덮어쓰지 않고 오류를 표시합니다.

일반 C#으로 완전히 전환하려면 프로젝트 밖에 생성 C#을 먼저 백업하고, Unity에서 한씨 원본을 삭제해 가져오기가 끝난 뒤 C# 백업을 복원합니다. 생성 파일 첫 줄의 소유권 표식도 제거하여 직접 관리하는 C#임을 명확히 하세요. MonoBehaviour를 유지한다면 기존 `.cs.meta`도 백업·복원해 씬/프리팹 참조가 바뀌지 않게 하고, 전환 후 참조와 컴파일을 확인하세요.

이름을 새로 만드는 방식으로 전환하면 클래스명·파일명을 함께 바꾸고 컴포넌트 참조를 다시 연결해야 합니다. 원본을 지우기 전에 백업하세요.
